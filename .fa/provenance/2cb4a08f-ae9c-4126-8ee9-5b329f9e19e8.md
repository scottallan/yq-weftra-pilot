## Clarifying Q&A

**Q:** Is comment preservation across mutation required (as in the issue's worked example, where a `//` comment must survive a field being added), or is JSONC support satisfied by round-tripping trailing commas plus comments only when the document is unmodified/passed through unchanged?

**A:** Preservation across mutation is required. The issue's worked example is the acceptance case: the file has a `//` head comment and a trailing comma, the expression adds a field, and the output keeps the comment and the new field together. Comments should attach to the nodes they annotate the same way yq already keeps YAML comments through edits (head/line/foot comments on the CandidateNode), so a comment on an untouched node survives any mutation elsewhere and is emitted again by the jsonc encoder. Trailing commas are an input-only tolerance: accept them when decoding jsonc; do not emit them. Where a comment attaches when it is ambiguous, follow whatever rule the existing YAML decoder uses for the same position, and say so in the docs. Passing a jsonc document through unchanged must round-trip comments too, but that alone does not satisfy the request.
